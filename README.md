# 💖 Birthday Surprise for Harshithaa

A romantic birthday website made with only HTML, CSS and JavaScript. It is free to host on GitHub Pages. There is no backend, no build step and no paid service.

**Flow:** Heart screen → tap the big button → birthday message → 7-photo gallery → little door, a character knocks, four cats come out → "Happy Birthday, Harshithaa!" → Replay button.

There is **no pull arrow, no dragging and no swiping** anywhere. Everything works with a simple tap.

---

## ⚠️ READ THIS FIRST: do not upload the ZIP

The ZIP is only for carrying the files to your phone. **Do not upload the ZIP file to GitHub.** GitHub cannot run a website from inside a ZIP, and you will get a 404 page.

1. **Extract** the ZIP on your phone (steps below).
2. Upload the **extracted files themselves**.
3. `index.html` must be in the **main (root) level** of the repository, not inside a folder.

---

## 📁 What must be in the repository root

All files sit **side by side**, with no sub-folders. That makes uploading from an Android phone easy.

```
your-repository/
├── index.html      ← the website (must be named exactly this, all lowercase)
├── photo1.jpg      ← your photos (you add these)
├── photo2.jpg
├── photo3.jpg
├── photo4.jpg
├── photo5.jpg
├── photo6.jpg
├── photo7.jpg
└── README.md       ← this file (optional, you may skip uploading it)
```

There are no other assets. The music is generated by the browser, and the cats, door and character are drawn in code, so there are no audio or video files to lose.

## 🖼️ Step 1: Add your 7 photos

1. Rename your seven photos to **exactly** `photo1.jpg`, `photo2.jpg`, … `photo7.jpg`.
2. Put them in the **same folder as `index.html`**.

**Photo rules (GitHub Pages is case-sensitive):**
- `photo1.jpg` works. `Photo1.jpg`, `photo1.JPG`, `photo1.jpeg` and `photo 1.jpg` **will not** load.
- iPhone photos are sometimes **HEIC** files. Browsers can't show those. Send them through WhatsApp or "Save as JPEG" first, or screenshot-crop them. Check that the name ends in `.jpg`.
- Keep each photo under about **1–2 MB** so the page loads fast on mobile data.
- If a photo is missing, the page shows a pink heart card instead of breaking.

Photos are shown whole (never stretched or cropped), so portrait and landscape both look right.

## 💻 Step 3: Test locally before publishing

**On a computer:** double-click `index.html`. It opens in Chrome. Tap through everything using the checklist below.

**On an Android phone:** opening local files is awkward, so the best test is to publish (Step 4) and test the live link. It's free and you can change it any time.

## 📱 Step 4: Publish for free from an Android phone

1. **Download** the ZIP to your phone, then open the **Files** app (or "Files by Google").
2. Long-press the ZIP → **Extract** (or tap it → **Extract**). You now have a normal folder. Open it and check that you can see `index.html`.
3. Add your 7 photos into that folder, named `photo1.jpg` … `photo7.jpg`.
4. Open **Chrome** and go to **github.com**. Sign in, or create a free account. If the page looks cramped, tap Chrome's ⋮ menu → tick **Desktop site**.
5. Tap **+** → **New repository**.
   - Repository name: something simple like `harshithaa-birthday` (lowercase, no spaces).
   - Choose **Public** (free GitHub Pages needs a public repository on free accounts).
   - Tap **Create repository**.
6. On the new empty repository page, tap **uploading an existing file** (or **Add file → Upload files**).
7. Tap to choose files, and pick **`index.html` and all 7 photos** from the extracted folder. Select the files, not a folder and not the ZIP.
8. Check the list on the screen:
   - ✅ exactly one `index.html`
   - ✅ `photo1.jpg` … `photo7.jpg`
   - ❌ no files named like `index-8.html`, `index (1).html` or `index.html.txt`
9. Scroll down and tap **Commit changes**.
10. **Turn on GitHub Pages:**
    - Open the repository's **Settings** tab (you may need to scroll the tab row sideways).
    - Tap **Pages** in the left menu.
    - Under **Build and deployment → Source**, choose **Deploy from a branch**.
    - Under **Branch**, choose **`main`** and the folder **`/ (root)`**, then tap **Save**.

### ✅ How to confirm it deployed

- After 1–3 minutes, refresh **Settings → Pages**. A box appears saying **"Your site is live at https://…"**. Tap **Visit site**.
- Or open the **Actions** tab. A run called **"pages build and deployment"** should show a green ✅. A yellow dot means it's still working. A red ✖ means it failed, so open it to read why.
- Only the green ✅ means the website exists. Before that you may see a 404, and that is normal.

## 🔗 Repository link vs. live website link (the thing that causes the confusion)

| | What it is | Looks like | What you see |
|---|---|---|---|
| **Repository link** | The folder of code on GitHub | `https://github.com/USERNAME/harshithaa-birthday` | GitHub's code pages, **not** the surprise |
| **Live website link** | The actual surprise site | `https://USERNAME.github.io/harshithaa-birthday/` | The heart and the "Tap to Open" button |

- The live link is: `https://` + your username in **lowercase** + `.github.io/` + the repository name + `/`.
- **Send Harshithaa the `github.io` link**, never the `github.com` link.
- The live link only works **after** Pages shows a successful deployment.

**If you see a 404 page:**
1. Pages is not turned on yet (Settings → Pages → `main` / `/ (root)` → Save).
2. You uploaded a ZIP or a folder, so `index.html` isn't in the root.
3. The file isn't named exactly `index.html`.
4. You opened the `github.com` link instead of the `github.io` link.
5. It's still deploying. Wait 2–3 minutes and check the Actions tab.

**Why you got `index-8.html` before:** Android adds a number to a file name when a file with the same name is already in Downloads, so you end up with names like `index (8).html`. Rename the file to exactly `index.html` before uploading, and delete any extra copies in the repository (open the file → 🗑 delete).

## 🔄 After you change something: hard refresh

Phones and GitHub cache pages, so you may keep seeing the old version.

- **Android Chrome:** open the live link, tap ⋮ → **Reload** a couple of times. If it still looks old, add `?v=2` to the end of the link (for example `https://USERNAME.github.io/harshithaa-birthday/?v=2`).
- Or open it in a **new Incognito tab**, which never uses the old cache.
- **Desktop Chrome:** press **Ctrl + Shift + R** (Windows) or **Cmd + Shift + R** (Mac).
- After uploading a changed file, wait 1–2 minutes for the green ✅ in the Actions tab before refreshing.

## 🔊 About the music

- The music is a cheerful "Happy Birthday" tune made live by the browser (Web Audio API), so there is **no audio file** and no licensing problem. The tune itself is the traditional, public-domain melody.
- It starts only after the first tap, because phones don't allow autoplay.
- **iPhone tip:** if you hear nothing, flip the **silent switch** on the side of the phone to ring mode and turn the volume up. iPhones mute web audio when silent mode is on.
- If audio is blocked or not supported, the site still works and just stays quiet.
- If you open the link inside the **WhatsApp in-app browser** and want the music louder or more reliable, tap ⋮ → **Open in Chrome**.

## 🧰 Quick troubleshooting

| Problem | Fix |
|---|---|
| 404 page | See "If you see a 404 page" above |
| Old version showing | Hard refresh (above) |
| A photo shows the pink heart card | File name must be exactly `photoN.jpg` (lowercase) and in the same place as `index.html` |
| Fonts look plainer | The fancy fonts load from Google Fonts. With no internet the page falls back to built-in fonts and still works |
| Music silent on iPhone | Turn off silent mode and raise the volume |
